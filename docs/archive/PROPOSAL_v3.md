## 0. TL;DR

1. **一句话定位**：**用 demo 换运行期预算**——把本来需要模型在线试探才能获得的任务结构，用一段 demo 离线买断，运行期只留下「有界修正」这一条最小自由度。
2. **主张**：机器人操作中真正稀缺的知识不是「怎么动」，而是「什么必须成立、按什么顺序成立、哪里可以松」。这类知识常识给不了、当前观测也给不了，**只有 demo 能给**。
3. **推论**：既然这类知识是关系型/离散型/分级型的，它的正确形态就是**约束**——不是轨迹，不是数值点位，不是「记住 demo 抓在哪」。
4. **框架**：demo → 带类型空洞的约束图 → 编译成 code policy → 运行期两级闭环（node 间 gate 可否决 / node 内有界修正）。
5. **分工裁决**：**demo 负责目标与结构，在线模型只负责手段**。在线模型不产生新目标、不参与验收、只输出限幅增量。
6. **系统立场**：把力气放在 harness 和 infra 上，让 frontier 模型既写代码又做闭环；**拒绝把人手写的任务 service 和 yaml 喂给模型**——那是「测 agent」与「测 yaml 作者」的分界线。

## 1. 一段 demo 到底提供了什么信息

先问一个能把全案定死的问题：**在常识和当前观测都已充分的前提下，demo 还剩什么不可替代的贡献？**

如果答案是「没有」，那 demo 就该被删掉，直接上语言指令 + 在线 VLM。所以本案成立与否，取决于下表能不能站住。

| 知识类别 | 具体指什么 | 常识为什么给不了 | 当前观测为什么给不了 | demo 给出的形态 |
|---|---|---|---|---|
| **歧义消解** | 同一句指令有多个物理上都成立的解法 | 语言欠定，模型会挑一个「平均解」 | 观测只说「场上有什么」，不说「该选哪支」 | 哪一支被选中（离散选择） |
| **技巧** | 非直觉的中间做法（先对中再落、先贴边再压） | 常识知道终局，不知道招式 | 观测看不到「本可以但没走」的路径 | 必须途经的中继条件 |
| **容差** | 哪个自由度必须紧、哪个可以松 | 常识只有「大概对齐」这种平均描述 | 观测给不出松紧，只给出当前值 | 各约束的紧/松分级 |
| **恢复结构** | 出错后退回哪里可救、哪种错不可救 | 常识默认「再试一次」 | 单帧观测判不出可逆性 | 哪些节点可重入、哪些是不可逆闸门 |
| **前后依赖** | 顺序与互斥 | 常识给的顺序常常只是习惯 | 观测只有当前时刻 | 图的拓扑 |

**关键观察**：这五类没有任何一类天然是「某个 6-DoF 数值」。它们全是关系、离散选择或分级。

**因此**：把 demo 编码成轨迹或点位，是把一个关系型信号强行投影到数值空间——投影会同时丢掉信息（容差、可逆性）和引入伪信息（那个具体坐标只对当时那个场景成立）。

> **本案的第一条锋刃：demo 的产物必须是约束图，不是轨迹，不是点位。**
> 数值不来自 demo，数值来自运行期的感知。

## 2. 从「约束」推出框架的其余部分

### 2.1 为什么是 typed holes（带类型的空洞）

约束图说的是「此处需要一个满足关系 R 的抓取」，而不是「抓在某坐标」。于是图里天然留下**带类型的空洞**：抓取关系槽、放置关系槽、affordance 位置槽、顺序槽。空洞的类型由 demo 定，空洞的取值由运行期感知填。

**空洞由候选填，不由文字填。** 让模型用自然语言描述几何（「抓在碗沿偏左三分之一处」）是个死结：文字对几何的分辨率远低于任务需要的分辨率。改为让感知模块（如 GraspNet 一类）产出**候选集合**，模型只做**选择**。选择是模型擅长的、可枚举的、可复核的；描述几何不是。

**候选处理的完整链条**（这一条比「离散化」本身更重要）。统一表述为**三层漏斗 + 第 4 步选择**。⚠️ 本节的漏斗 L1/L2/L3 与 §3.1 的信息流层 L1–L5 **不是同一套编号**，任何报表、图注、消融表都必须写明引用的是哪一套：

```
候选生成器给出数值候选（位置 / 接近方向 / 闭合轴）
  → 漏斗 L1 硬可行性一票否决（可达、无碰撞、开口合法）——任务无关；
     **这是唯一允许淘汰候选的层**
  → 漏斗 L2 偏好排序（**不淘汰**）——demo 约束编译成**任务无关的单调偏好函数**，
     把定性几何知识（如「抓中上部」）变成对候选的**排序**；
     它既不是判别器，也不是数值的生成器
  → 漏斗 L3 下游约束反推——这个抓法会不会让后续节点不可能完成
     （插入时夹爪撞架、重力转不正）；允许改序，极端情形允许否决
  → 第 4 步 选择：v1 走**确定性 CandidateSelector**（三态，无 LLM）；
     **模型 tie-break（必须引用约束说理）挂起**，解冻条件见 §5
```

**「排序偏好」裁决的回灌（2026-07-30）**：漏斗 L2 由淘汰语义改为排序语义——**它不再产生任何淘汰计数，只产生排序变化**。这消掉了「谓词阈值 0.5 从哪来」这个质询面。**作用范围必须写清楚**：本次裁决只覆盖 **region**；**cone 是否同样改排序偏好尚未裁决**，在裁决落账前 cone 保留硬阈值，「25° 从哪来」的质询面仍然敞着，不得对外宣称已消除。下游判据 CC-0 / CC-1′ / CC-2′ 以本节为上位依据。

三条纪律：

1. 模型**只选不写**（选择候选，绝不生成数值）；
2. **偏好函数必须任务无关且单调**——全任务共用一套，不得 per-task 手调，不得含任务名或任务特定阈值；
3. 候选过多时不允许自由挑（必须先过漏斗，再在有序前缀内选）。

**「下游约束反推」（漏斗 L3）是 demo 约束在抓取阶段唯一不可替代的作用**——纯几何模块懂几何不懂任务，看不出这个抓法会在三步之后害死自己。它同时是判据 P-3′（L3 在 counterfactual 上 ≥1 次改 top-1）的唯一载体。**v1 落点**：漏斗 L3 **不进 MVS**，由 P1-09 承载；**MVS 阶段实际运行的漏斗只有两层（L1+L2），任何报表不得写成三层。**

### 2.2 为什么要编译成程序

约束图是声明式的，机器人需要可执行物。程序是唯一同时承载顺序、条件、参数绑定、可复算的载体，并且：

- **可审计**：程序可读、可 diff、可被单点否决；黑箱策略不行。
- **目标显式化**：编译过程把「这一步的目标约束」算出来并写死在程序里。这一步至关重要——**它给了运行期修正一个目标**。否则在线模型只能自己现想目标，那就退化成「从零决策」。

### 2.3 为什么必须是两级闭环，而不是一级

code policy 是开环的，执行期一定有误差。但误差有**两种性质完全不同**的来源：

| 误差性质 | 例子 | 可修性 | 正确处置 |
|---|---|---|---|
| **结构性失败** | 完全没抓到、抓反了、抓错物体 | 基本不可修，后续调整代价极高 | **早 reject**，不要浪费预算去「调整」 |
| **位姿微差** | 插入差几度、碗在夹爪里不平、碗心未对齐 | 可修，但不可事先预测 | **在线看、有界修正** |

gate 必须存在的最经济论证：**误差的可修复性随阶段推进单调下降；抓反之后，所有下游修正都是在错的流形上挣扎。**

- 只做 gate：会把本可救的微差直接判死，任务成功率被 gate 自己压掉。
- 只做修正：不可救的结构性失败会被无限次「调整」，把预算烧光并制造假象。

### 2.4 两级闭环的分工（code-as-policy 给结构，ReAct 给误差消除）

与「让模型从零操作」的 agent-in-the-loop 路线的根本差别：**我们的在线模型从不面对空白任务，它永远面对一个已经被写死目标的局部问题。**

| | ① node 间 gate | ② node 内有界修正 |
|---|---|---|
| 触发时刻 | 一个节点的动作序列跑完 | 验收未过，但偏差在可挽回范围 |
| 问题形式 | 当前约束是否满足？能否进下一节点？ | 在已知目标约束下，如何减小偏差？ |
| 输入 | 验收谓词结果 + 独立感知证据 | 上一节点实际结果 + 编译期算出的**目标约束** + **多视角画面** |
| 输出 | pass / retry / **reject** / 回退到指定节点 | 一个限幅的、体固定坐标系下的增量 |
| 失败处置 | 结构性失败直接 reject，不进下一节点 | 修正预算用尽 → 交回 gate 判定 |
| 为什么必须有 | 可修复性随阶段单调下降 | 开环程序不保证零执行误差，误差来源不可预先枚举 |

程序给结构与目标，闭环给误差消除；两者的接缝就是**洞**和**限幅增量**。

### 2.5 关于「像伺服」的措辞修正

这一层**不是伺服**。一次模型调用是秒级，与伺服的控制频率差好几个数量级。正确的名字是 **bounded correction / deliberative step**：低频、离散次数、有预算上限的审慎修正步。

同样地，**不承诺「残差可解析」**。本栈上 pose-in-hand 的偏差来源复杂且不可直接测量，「算出残差再按残差修正」的路线在实践中反复失效（越修越坏）。v3 的表述是：**基于视觉证据的有界修正**——模型看图、给方向性的小增量、看结果、再决定继续或停止。它不需要知道残差是多少，只需要知道往哪边一点点。

## 3. 框架总览

### 3.1 信息流层

| 层 | 输入 | 输出 | 是否任务特定 | 运行期是否活动 |
|---|---|---|---|---|
| **L1 约束抽取** | demo 视频 + 指令 | 约束图：节点 + 完成条件 + 容差分级 + 拓扑 | 是（这是 demo 的全部价值） | 否（离线完成，运行期不再看 demo） |
| **L2 空洞绑定** | 约束图 + 运行期感知候选 | 被填实的参数 | 否（绑定规则任务无关） | 是（每集绑定一次；**v1 为确定性无 LLM 路径**，§2.1 第 4 步的模型 tie-break 挂起） |
| **L3 编译** | 约束图 + 绑定 | code policy（含每节点的目标约束） | 否（**编译器本身通用**；任务特定性只存在于它产出的那份程序里） | 否 |
| **L4 节点门控** | 节点完成条件 + 观测 | pass / retry / **reject** | 否 | 是 |
| **L5 有界修正** | 上一节点结果 + 目标约束 + 多视角图像 | 限幅增量 | **否（必须任务无关）** | 是 |

允许 L1 / L3 / L5 使用**不同的模型**。唯一的硬约束是 L5 必须任务无关。

> **编号提醒**：本表的 L1–L5 是**信息流层**；§2.1 的 L1/L2/L3 是**候选漏斗层**。两套编号互不通用，交叉引用时必须带前缀（「信息流 L2」/「漏斗 L2」）。

### 3.2 执行主体与决策权

信息流不等于执行权。硬边界需要有组件承载，否则只是悬空的规则。

| 角色 | 决定什么 | **不**决定什么 | 边界为什么划在这里 |
|---|---|---|---|
| **demo 视频** | 节点划分、每节点必须成立的关系、顺序依赖、什么算完成 | 任何世界坐标下的度量值、抓取点位、轨迹 | 度量值绑定在示范当时的场景与本体上，换场景即失效；关系不会 |
| **编译期模型** | 把 demo 读成结构并写成程序；为每个空洞指定求解器与合法域 | 不得写死场景度量常数；不得发明 demo 里没有的目标 | 模型对数字缺乏物理校验能力，写下的常数只是搬运 |
| **运行期模型** | 在**已给定目标**下，此刻朝哪个方向、动多少 | 不判定成败；不输出关节角/绝对位姿/数值常数；不改目标与顺序 | 评判者与被评者必须分离；在线自由度必须小到可审计 |
| **感知 / 求解器** | 所有数值 | 不决定「要不要继续」 | 数值只能来自测量，不能来自语言 |
| **候选生成器** | 提出数值化候选集合 | 不决定选哪个 | 生成器懂几何不懂任务；任务偏好在约束里 |
| **可信 runner** | 按程序调用最底层原语；执行限幅、预算、超时 | 不解释语义、不做补救决策 | **唯一有权动机器人的组件必须是不可被说服的**；越界时拒绝并记录，而不是截断后照做 |
| **验收器** | 每节点是否达成、是否离谱、整集是否成功 | 不参与动作生成 | 在线模型的输出绝不进验收——全案唯一不能让步的一条 |

## 4. 三条不可协商的硬边界

1. **在线模型的输出只能进动作调用，绝不能进验收。** 一旦模型能影响成败判定，策略就可以通过「宣称成功」来优化指标，全部实验作废。验收必须来自独立于在线模型的通道。
2. **在线模型只输出限幅的、体固定坐标系下的增量。** 不输出关节角、不输出绝对位姿、不输出任何数值常数。越界由 runner 拒绝并记录。
3. **运行期模型调用必须有每集预算上限**，且「预算耗尽 / 服务异常」与「任务失败」在记录上必须可区分。否则失败分析会把基础设施问题误读成方法问题。

## 5. 「冻结」的可操作定义

旧说法「运行期无 LLM = 冻结」在本框架下自相矛盾（L5 本身就是 LLM）。**冻结的对象是任务特定信息，不是 LLM 调用。**

**与 D-01 的关系（必须留痕，不得就地删改）**：本节**明确撤销 D-01 的「执行期零 LLM」口径**，同时**保留 D-01 的两条理由**——① **摊销**：相对 per-episode VLM 路线的成本/延迟优势仍是主要可防守点；② **可审计**：冻结后换 seed/layout 只有感知返回值变化，失败可归因到具体约束。新口径下这两条由「运行期不注入任务特定信息 + 每集预算上限（硬边界 3）+ 输出面只有限幅增量（硬边界 2）」承接，而不是靠「一次 LLM 调用都没有」来保证。

程序上：需在 `DECISIONS.md` **新增 D-18**，把 D-01 改判为「**已撤销（口径），理由保留**」，**不要修改 D-01 原文**（D-16 纪律）。在 D-18 落账前：

- L4 verifier 与 L5 corrector 两个运行期模型工位处于 **BLK-5 阻塞**（见 `EXECUTION.md` §6-1）；
- **§2.1 第 4 步的模型 tie-break 同属被撤销口径的适用面**，v1 一律走确定性 CandidateSelector，不启用模型 tie-break；
- 任何把运行期模型工位写成「已放行」的文档或报表，视为越过治理面。

三条同时成立才算冻结：

- **逐字不变**：修正器 prompt 与工具集跨任务逐字相同，不含任务名、物体名、任务特定阈值或提示。
- **交换测试**：把任务 A 的修正器原样用于任务 B。若性能不掉，说明修正器确实没有偷藏任务知识；若掉，说明存在泄漏，冻结主张不成立。
- **字面量扫描**（可自动化、无争议）：策略程序里出现任何场景度量字面量即判失败。前两条依赖人工判读，这一条不依赖。

同理，约束图在编译完成后冻结：运行期不重读 demo，不新增节点，不新增目标。

## 6. 假设与证伪

每条机制都必须能被杀死。

| # | 假设 | 若为假，会观测到什么 | 证伪设计（概念层） |
|---|---|---|---|
| **A1** | demo 的增量在**约束**而非点位 | 把 demo 降级为「只给语言指令」或「只给数值点位」后，性能不显著下降 | ① 三臂消融：全约束图 / 仅点位 / 无 demo；② **结构等价性检查**：换一段同任务、不同摆放的 demo，若抽出的约束图不结构等价，则学到的是这一段录像而不是这个任务；③ **成对实验**：同指令、不同 demo，系统须各学各的 |
| **A2** | **目标由 demo 定、手段由在线模型定**这一裁法正确 | 放开在线模型新增目标后性能显著更好 | 放开/收紧目标权限的对照臂；两端对照（纯离线开环 / 纯在线即兴） |
| **A3** | 结构性失败可被**早期**判定 | gate 判定与最终成败在人工标注上不相关 | ① 用离线标注评估 gate 判定与终局的一致性；② **误杀率反向检查**：统计被 reject 的集里有多少其实还能救回来——比例过高说明这是「提前放弃」而非「早止损」，判据应放宽或降级为 retry |
| **A4** | 有界修正对位姿微差**有效**，且「带目标」是它新颖性的来源 | 开/关修正器不可区分，或修正使结果变差 | ① 开/关修正器成对对照；② **目标剥离**：把编译期算出的目标约束从 context 拿掉只留图像——若性能不降，则退化为普通 VLM 纠错，本机制新颖性消失；③ 多视角 → 单视角对照 |
| **A5** | 候选**选择**优于文字描述几何，且模型带来了任务语义 | 模型选择不优于**随机序**，也不优于**无偏好的可行性序** | 四臂对照：① 模型自由描述几何；② **null-A**：过漏斗 L1 后**随机取**；③ **null-B**：过漏斗 L1 后按生成器原始置信度取 top-1（**无偏好**）；④ 我方（漏斗 L2 偏好序 + 第 4 步选择）。**不得再用「候选中几何打分 top-1」当 null**——排序偏好裁决后漏斗 L2 本身就是确定性单调几何打分，拿它当对照会让我方与 null baseline 收敛为同一个东西，A5 退化为同义反复 |
| **A6** | 冻结成立（无任务泄漏） | 交换测试掉性能 | 跨任务交换修正器 + 字面量自动扫描 |
| **A7** | 薄底座（仅底层原语）足以表达任务 | 底层动作面连 demo 本身都复现不了 | 把「动作面的抽象层级」当实验变量：仅底层原语 vs 额外允许人手 yaml（见 §8） |

> **A5 的可测时点**：A5 的「模型语义贡献」臂依赖 §2.1 第 4 步解冻（即 D-18 落账后重开模型 tie-break）。v1 期间只能跑 null-A / null-B / 漏斗 L2 三臂，得到的结论是「**偏好排序 vs 无偏好**」的效应，**不得报为「模型带来任务语义」**。

**A1 与 A2 是本案的存亡假设**：A1 假则 demo 无价值，全案退化为 CaP；A2 假则赌注方向错误，应转向「任务知识在线获取」那一边——但那样就必须放弃「离线固化约束图」的全部投入。v3 明确选定 A2 的当前裁法，并接受它是可被证伪的选择而非公理。

**归因准入条件**：每一次失败都必须能定位到「**哪个节点 × 哪一层**」。做不到归因的实验不计入结论。这是本框架相对端到端路线的主要方法论优势，放弃它等于放弃立论基础——所以它是准入门槛，不是加分项。

## 7. 与相邻工作的差异：各自的赌注与暴露面

| 路线 | 它赌什么 | 代价 / 暴露面 |
|---|---|---|
| **轨迹模仿 / 人视频转数据** | 任务知识可压进「像素→动作」的对应里 | 学到的是点位而非关系；换摆放即失效；约束不可读、失败不可归因 |
| **每集在线构造约束（ReKep / CoPa 类）** | VLM 每一集都能把任务在线写成关键点约束 | 每集重付一次结构推理；结构对不对无法跨集复用；约束必须落进求解器可吃的形式 |
| **code-as-policy + 逐轮重写（CaP-X 类）** | 常识足以补全任务结构，靠反复重写代码收敛 | 任务特定的容差、歧义、技巧无从获得；失败沿整条代码链传播到末端才被发现；运行期预算不封顶 |
| **agent 每步在环（VIA 类）** | 模型每一步都能判断该做什么 | 预算与延迟随步数线性增长；策略不可复现、不可审计；无法把失败归到某一层 |
| **VLA / BC** | 端到端能吃下一切 | 约束不可读；无法做节点级判定；无法早止损 |
| **人手 yaml 技能栈** | 人预先写好的任务级 service 覆盖得住 | 见 §8 |

> **共同的空档**：上面每条路线都把「任务结构」放在两个极端之一——要么烧进权重（不可检验），要么每集在线重推（重复付费）。**没人把它当作可离线固化、可检验、可复用的中间产物。**

本案就站在这个空档里：demo → 约束图 → 程序，是一个可读、可 diff、可消融、一次付费的中间产物。

## 8. 接口纪律：为什么拒绝人手 yaml

> **一个技能栈的可用动作面，等于历史上人写过的 yaml 的投影。**

如果 agent 只能调用人已经为这些任务写好的 service 和 yaml，那么实验测的就是**那些 yaml 写得好不好**，而不是 agent 强不强。

| 给模型什么 | 实际在测什么 |
|---|---|
| 任务专用 service + 参数 yaml | 人类先验的覆盖度；模型的填空能力 |
| 最底层控制原语 + 通用感知/推理接口 | 模型自己构造技能与闭环的能力 |

**可判定的违规规则（二值，不需要争论）**：**接口、原语或配置中出现任务名 = 违规**。允许补充底层原语，但补的必须是任务无关的能力。

**把纪律做成可证伪主张**：把「动作面处在哪个抽象层级」当作实验变量——同一 agent 在（a）仅底层原语 +通用推理服务 与（b）额外允许人手 yaml 两种动作面下对比。若差距不显著，接口纪律的主张失效（我们白付了成本）；若 (b) 显著更强，则说明该类报告中的能力大部分来自 yaml 作者。**两个结果都有信息量。**

**止损路径**：若纯底层动作面连 demo 本身都复现不了，说明线划错了——届时允许**自动生成的**中间层（生成器在线、不含任务先验），但**绝不退回人手 yaml**。

**代价如实认领**：底座越薄，失败越多、调试越难、早期成功率越低。这是本案自愿承担的难度，也是它值得做的原因——目标是找到能**自迭代技能**的方法与系统，而不是在既有技能库上刷分。因此低早期成功率本身不构成对方法的反驳；构成反驳的是失败集中在「原语组合」而非「任务理解」。

## 9. 范围与通用性

- 框架的目标是通用；stack_bowls / insert_tubes 只是**最小可证伪例**，因为它们的约束结构简单到可以被完整写清。
- 通用性的证据来自**约束类型覆盖**，不是任务数量。任务集必须至少覆盖两类性质不同的约束（如「对中/插入」的紧公差方向约束 vs 「堆叠/平衡」的姿态平齐与中心对齐约束），且修正器跨类逐字不变。
- 靠加同类任务刷数量，不构成通用性证据。
- 任务专用性只允许存在于「从 demo 编译出来的那份程序」里。若必须为新任务手写框架组件，通用性主张即被削弱。

## 10. 风险与止损（只写性质）

| 风险 | 表现 | 止损动作 |
|---|---|---|
| **约束抽取不稳** | 同一 demo 两次抽出结构不同的图；换 demo 结构不等价 | 先把「抽取的可重复性」当作独立问题测；若不稳，退到「人给图结构 + agent 填空洞」，同时把论文主张相应收缩到空洞绑定层，不假装图也是自动的 |
| **约束退化为点位** | 分布外重排即崩 | 主张从科学贡献降级为系统贡献，明确写出 |
| **偏好排序层退化为纯几何** | 我方漏斗 L2 与 null-B（无偏好可行性序）不可区分 | 按 §6-A5 的四臂结果处置：若偏好序不优于 null，则「demo 约束参与候选排序」这一机制降为实现细节，论文不得声称它承载任务语义 |
| **修正器越修越坏** | 开修正器组不优于关修正器组 | 修正必须限幅 + 有预算 + 永远保留「不修」对照；若在对照上不占优，**删掉这一层**而不是继续调 prompt |
| **gate 误杀过多** | 大量可救回的集被 reject | reject 只保留最极端一类，其余降级为限预算 retry |
| **在线模型污染验收** | 成功率异常好且失败模式消失 | 验收通道与在线模型物理隔离；一旦发现耦合，该批结果全部作废 |
| **接口纪律拖慢一切** | 缺原语导致无法表达某类动作 | 允许补原语，但按 §8 的二值规则判定；宁可任务做不成，也不引入带任务名的接口 |
| **两条赌注混用** | 同时声称「知识可离线固化」和「知识须在线获取」 | 已按 §2 与 §3.2 裁定；任何要求在线模型新增目标的改动，视为切换赌注，必须重新声明主张并重打两边 baseline |
| **预算/服务不稳污染结论** | 失败原因不可分 | 硬边界 3 是实验准入前置条件；不满足则该批数据作废 |
| **治理面与方案面不同步** | 同一条裁决在 DECISIONS 生效、在本文已废（D-01 曾如此） | 任何撤销必须新增裁决 ID 留痕（§5 的 D-18 路径），旧条只改状态不删正文；未落账前相关工位一律按阻塞处理 |

## 11. 明确不做的事

- 不做端到端训练，不产出新的 VLA。
- 不追求全程单一模型；写代码的模型与在线修正的模型可以不同。
- 不承诺可解析的残差，不承诺伺服级频率。
- 不在运行期引入任何人手编写的任务特定脚本或 yaml。
- 不用示例任务定义方法边界——它们是最小验证载体，不是方法的适用范围。

## 12. 开放问题（本框架目前没有答案的地方）

1. **约束图的表达完备性未知。** 目前的节点/关系/容差分级形式能覆盖对齐、插入、堆叠这类几何约束，但对「力/柔顺约束」（拧紧到某个手感、按压到某个阻力）、「时序约束」（保持接触若干秒）、「多臂协同约束」是否够用，没有答案。也没有一个判据能说明「这个任务的约束表达不出来」与「这个任务的约束抽错了」的区别。
2. **容差分级从何而来。** 主张是「demo 给出紧/松分级」，但单段 demo 原则上只展示了一次成功，成功不蕴含边界。多段 demo 的方差是否等于容差、还是仅仅等于演示者的抖动，尚未有原理性的区分方法。
3. **约束图的可组合性未验证。** 若两个任务的约束图共享子结构，能否复用？框架目前假设每个任务编译一份图，没有回答「图之间是否构成一个可增长的库」——而这正是「技能自进化」主张的必要前提。
4. **「有界」的界从哪来。** 限幅是硬边界，但幅度的量级本身若需按任务调，冻结主张就被从后门破坏。目前只知道它必须任务无关，不知道它该由什么原理确定（本体尺度？感知不确定度？）。
5. **gate 判据与修正目标同源带来的循环风险。** 两者都来自约束图。若约束抽错，gate 会一致地判错、修正会一致地朝错误方向走，且系统内部无任何信号能发现这一点。目前唯一的破环手段是外部人工标注，这不可扩展。
6. **在线模型「不产生新目标」是否可被强制。** 硬边界靠输出格式约束（只出限幅增量）实现，但模型可以用一连串合法的小增量实现一个 demo 里不存在的宏观目标。是否存在一种检验能识别「增量序列在实现隐含新目标」，未知。
7. **两级之间的仲裁没有原则。** gate 说「不过」、修正器说「还能再试」，谁优先？目前靠预算硬切，但这是工程妥协不是原理。
8. **失败归因的粒度上限。** §6 要求归因到「节点 × 层」，但当误差跨节点累积（前一节点合格但贴着容差边缘，导致后一节点必然失败），归因会指向后者。框架目前没有表达「边缘合格」这一状态的位置。
9. **偏好序的「正确性」没有独立参照。** 排序偏好裁决消掉了阈值来源的质询面，但代价是漏斗 L2 不再有二值对错——一个坏偏好函数只表现为排名靠后，不表现为可计数的错判。目前除了终局成功率，没有任何中间信号能说明「这个偏好序排错了」。
10. **cone 类约束的处置未裁决。** region 已改排序偏好，cone 仍是硬阈值（25°）。两类约束是否应统一语义、还是方向类约束天然适合硬阈值，没有原理性回答。
