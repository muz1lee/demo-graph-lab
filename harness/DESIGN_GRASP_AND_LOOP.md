# 设计裁定:抓取姿态、pose-in-hand、以及「运行期闭环由谁来闭」

2026-07-30。触发:①用户指出"夹爪得朝下,但不是必须数值朝下,本质上是 pose in hand";
②用户建议接入 GraspNet 并从视频学抓取选择逻辑;③用户点出 inspect-robots 的真问题是
**ReAct 闭环是否可行**,而不是 servo。以下三条改的是方法设计,不只是实现。

---

## 1. 姿态不是目标,是约束 + 待估状态(取代"命令一个标准竖直四元数")

**旧做法(已证伪两次)**:算一个标准 top-down 四元数,命令手臂去到它。
第一次错在轴取反(把工具 +x 当接近轴,实为 +z);第二次错在即使给对了目标,
该臂在够物区也只转了 6°就停在偏离正下方 61°。**根因是这个做法本身有问题**:
它假设"存在一个正确姿态且手臂能到达",而真实系统里姿态是**可行域受限**的。

**新做法**:姿态从"命令值"降级为两件事的组合——
- **选择时的可行性约束**:候选抓取必须落在该臂在该位置真实可达的姿态子集内
  (这个子集要靠标定测出来,属于 per-robot 标定,不是 per-scene 数值,不违反 GT 防火墙)。
- **执行后的待估状态(pose-in-hand)**:抓完之后物体在手里是什么姿态,由感知估计;
  下游约束(管必须竖直入孔、碗必须水平叠放)据此反推腕部需要的补偿量。

于是"夹爪朝下"这个要求被正确地分解为:*不要求夹爪数值朝下*,而要求
**(抓取姿态, 物体在手姿态, 腕部剩余自由度)** 三者组合起来能满足下游约束。
这正是提案 §4.3 里 embodiment 论证的自然延伸,也是老板 07-29 就说过的原话。

## 2. 抓取候选选择:三层漏斗 + pose-in-hand 反推(GraspNet 接入后生效)

候选来源改为 GraspNet(移植中,服务端口 8115,对齐 CaP-X 协议:返回**相机系**位姿 + 分数,
TCP 偏移与世界系变换留给调用方)。选择逻辑:

| 层 | 判据 | 性质 |
|---|---|---|
| L1 硬可行性 | IK 可达 ∧ 无碰撞 ∧ 开口宽度 ∧ **姿态落在实测可达姿态域内** | 与 demo 无关,一票否决 |
| L2 demo 几何谓词 | 由 `region_grasp` / `approach_direction` 编译成可计算检验(抓在碗沿环带、管身中上部;接近仰角类别) | demo 提供,**只给关系不给数值** |
| L3 下游约束反推 | **pose-in-hand 可行性**:采用该候选后,物体在手的姿态 + 腕部剩余 DoF 能否满足放置/插入约束;以及 clearance(插到底夹爪会不会撞架子) | 本项目的可防守机制之一 |
| tie-break | 幸存者 ≤3 时才让 VLM 排序,并要求引用约束说理 | 可审计 |

L3 是关键差异:别人是"选最稳/最像 demo 的抓取",我们是**让未来的约束否决现在的抓取**。
counterfactual 实验(局部最优抓取 ↔ 下游不可行)是这条机制的证伪开关。

## 3. 被操作物体的 DoF 追踪:选最便宜的那条,不用 TAPIR

需求分两处,结论不同:

- **demo 侧(离线,可以重)**:提取"哪些 DoF 自由/锁定"需要看物体在演示中怎么动。
  用现成的 CoTracker(`components/video-perception-service` 已有),离线跑,重一点无妨。
- **执行侧(在线,必须轻)**:我们**不需要**逐帧密集追踪。采用
  **「抓取瞬间估一次 pose-in-hand + 用正运动学传播 + gate 失败时重估」**:
  1. 闭合后对物体分割一次、拟合轴/OBB(用 `services/common` 的 `sam_xquat:dof` 或我方
     `compute_obb`),得到物体相对夹爪的固定变换 `T_gripper→object`;
  2. 之后物体世界姿态 = 夹爪姿态 ∘ 该变换,**零额外感知成本**;
  3. 只有当阶段 gate 判失败(或接触事件发生)时才重估——因为滑动/碰撞正是使该变换失效的事件。
  这与「绑定时机」的设计同构:**入口绑定一次,失败驱动重绑**,而不是全程连续追踪。
  TAPIR/CoTracker 级别的在线追踪留作后备(仅接触段),不进 v1。

## 4. 运行期闭环由谁来闭:LLM 的三个位置(回应 inspect-robots)

`robocurve/inspect-robots` 的 agent policy 是**动作级 ReAct**:每步把相机图 + 状态喂给
frontier 模型,模型调 `move_to/move_joints/take_pic/done/give_up`,每次移动必须附一句
`note` 说明"看到什么、为何这样动";速度按量程比例限幅、单次 playout 上限 10 s,超了就
报 split-the-move 让模型自己拆;而且**它把"到位残差"回报给模型**,原文:
"The residual is the arrival check: a full step count alone does not prove the arm
reached its target when an approver rewrote actions or a smoothing controller blended
them." —— 与我们踩到的欠行程/假成功是同一个坑,他们的解法是**让模型看见残差**。

结论:**ReAct 不是伺服的替代品,而是 LLM 的另一个位置**。三个位置各有归属:

| 位置 | 谁在环 | 用途 | 对本研究的关系 |
|---|---|---|---|
| **A. bring-up / 标定** | LLM 在环,看图 + 看残差 | 摸清这台栈能做什么:可达姿态域、行程效率、哪种接近方式可行 | **实验室仪器,不是方法**。我手调伺服常数两次调错(接近轴、卡死阈值),这类栈特异性知识本就不该靠人猜——正该让模型看残差自己试 |
| **B. 方法(冻结)** | 运行期**无 LLM** | 编译好的约束程序 + 两级 ReAct 式闭环(阶段 gate + 有界修正),由**约束残差**驱动 | 核心主张:编译一次、冻结复用、毫秒级、可审计 |
| **C. 基线(论文用)** | LLM 每步在环 | `--policy agent` 就是我们提案里要的 **no-demo frontier agent 基线** | 直接给出摊销对照:他们每集 $4–15/最长 1 小时 vs 我们一次编译 ~$0.05 后无限复用 |

三点推论:
1. **立刻用 A**:今天卡住的姿态可行性问题,交给 ReAct 操作员比继续调伺服常数更快
   (已在跑对照实验:同一目标位姿,servo vs ReAct 各 3 次,比成功率/耗时/成本)。
2. **B 不变**:方法路径绝不把 LLM 放进运行期循环——否则核心主张自毁。
   但 A 阶段学到的**姿态可达域**可以作为 per-robot 标定烘进 L1 硬可行性层(与
   `CLAW_TIP_DZ` 同类,记录为标定值,非场景数值)。
3. **C 是白捡的基线**:inspect-robots 是 eval harness 形态、embodiment 可注册、
   模型走 OpenRouter 字符串——若能把我们的 sim 注册成一个 embodiment,
   就同时得到 no-demo 基线与 VLA 对照位。值得单独评估一次接入成本。

## 5. 与当前阻塞的关系

夹爪通道在本栈不通(v3 控制器每臂只出 7 DoF),**捏取类抓取现在不可能成功**。
但上面 1–3 全部可以在"不闭合夹爪"的前提下推进并验证:
GraspNet 出候选、三层漏斗筛选、pose-in-hand 反推的可行性判定,产出的是**候选质量指标**
(候选数、通过各层的比例、L3 否决掉多少个"看起来最优但下游不可行"的候选),
这本身就是消融 B 的数据。等夹爪通道修好,直接接上执行验证。
